# lit-rh-watch — 라이터 로빈후드 포인트 → LIT 전환 신호 감시

2시간마다 수집(`lit-rh-watch.yml`, GitHub 지연으로 실제로는 2~5시간 간격). 수집이 끝나면 바로 Brief Hub(`brief-hub.yml`,
`workflow_run`)가 outbox를 읽어 @spytltgld_strategy_bot으로 보낸다. 판정 코드를 push하면 그 자리에서 한 번 돈다.
대시보드: https://jinhae8971.github.io/korea-etf-calmar/lit-rh-watch/

| 신호군 | 원천 | 강신호(경보) 조건 |
|---|---|---|
| S1 온체인 | ETH·RH RPC `eth_getLogs`, RH `totalSupply`, Blockscout 주소 메타 | 풀 규모(1,100만±15%) 단건·7일 누적 / 신규 컨트랙트(14일 내) 수령 / RH체인 LIT 공급 +1M 이상 |
| S2 공식 | docs `.md` 3종 + 문서 전체 목록(`llms.txt`), `api.rh.lighter.xyz` 공지·리더보드 | 전환·청구·종료 키워드가 **새 문장**에 등장 / 목록에 전환 관련 **새 페이지** / 포인트 관련 공지 / 적립 48h 정지 / 상위10 합계 3%↓ |
| S3 앱 | 프론트 번들 모듈명·API 경로, 로컬 `account_probe`(인증) | 청구·보상 이름 신규 / 청구 API 배정값 등장(임박) |
| S4 보조 | Google News, X, Polymarket | 관찰까지만 |

등급: 조용함 → 관찰 → 경보 → 임박(서로 다른 신호군 2종 이상이 7일 안에 경보). 등급이 오를 때만 KST 07~21시에 보낸다.
판정 불가(핵심 원천 6종 중 3종 미만 수신) 2회 연속이면 잡 실패.

## 메시지

경보·임박: **무슨 일**(신호 이름 + 새로 들어간 문장 원문 + 잡힌 단어) → **의미** → **해제 조건** → 문서 원문·거래 내역·대시보드 링크.
시각은 감지한 때(밤에 감지한 것은 아침에 보내도 감지 시각 그대로). 텔레그램 HTML, 글자 잘림 없음.
보낸 경보가 풀리면 한 번 더 보낸다 — 오탐이면 **정정**, 해제 조건(되돌아온 LIT 등)이면 **해제**. 월초 1회 월간 점검.

## 문서 감시 규칙 (2026-10-22 오탐 뒤 보강)

그날 라이터가 문서 구조를 바꿨다(`points-program/…` → `programs/…`). 감시기가 옛 주소의 '페이지 없음' 안내문을 내용 변경으로 읽고,
키워드가 'recommended' 속 'ended', 'integration' 속 'ratio'에 걸려 경보를 냈다. 지금은:

- 키워드는 단어 경계로만 잡는다. 원래 있던 문장을 조금 고친 것(비슷한 옛 문장에 같은 키워드)은 관찰로 낮춘다.
- GitBook이 모든 `.md` 끝에 붙이는 'Agent Instructions' 안내문은 본문에서 뺀다.
- '페이지 없음'이 오면 기준선을 덮지 않고, 문서 전체 목록에서 같은 파일 이름(없으면 같은 제목)으로 새 주소를 찾아 따라간다
  (`state.doc_moves`). 옛 내용과 그대로 비교하므로 이전 중에 바뀐 내용도 놓치지 않는다. 못 찾으면 관찰 '찾을 수 없음'.
- 문서 전체 목록은 새로 생긴 페이지만 키워드로 본다 — 주소만 옮긴 페이지는 신호가 아니다.
- 규칙을 고치면 지난 문서 경보도 매 실행 다시 판정한다(`judge.rejudge`). 오탐으로 풀리면 정정 메시지가 나간다.

문서 이름표는 `watch_config.json`의 `doc_names`(파일 이름 기준)에서 붙인다.
