# catalyst-radar

시총 100위 내 **체인·프로토콜형 코인의 "예고된 미래 이벤트"를 D-day 로 관리**하는 독립 트랙.
기존 13종 자동화(가격·TVL 후행 관측기)는 수정하지 않는다.

## 왜 만들었나

2026-09-06 솔라나 생태계 급등을 기존 레이더 전부가 놓쳤다. 사후 확인 결과 원인은
정보 부재가 아니라 **그 종류의 정보를 읽는 센서의 부재**였다.

| 재료 | 공개 시점 | 급등 대비 선행 |
|---|---|---|
| SIMD-0550·0553 제출 | 2026-06 초 | 3개월 |
| 시그널링 임계 통과 | 08-05 | 32일 |
| 온체인 투표 개시→종료 | 08-22 → 08-27 | 10일 |
| Anza 로드맵 공개(Tx V1 9/9, Alpenglow 10월) | 08-29 | 8일 |
| 렌트 인하 1단계 활성화 | 09-03 | 3일 |

전부 날짜가 박힌 공개 일정이었다. 따라서 이 시스템은 확률을 예측하지 않는다.
**이미 확정된 캘린더를 남보다 먼저 읽는 것**만 한다.

## 유니버스 (기계적 판정 · 수동 목록 금지)

1. CoinGecko 시총 상위 100
2. DefiLlama 에 체인 또는 프로토콜로 등재 (`parentProtocol` 자식 승계 포함)
3. 자산형 토큰 제외 — 스테이블·랩드·상품(금)·거래소 토큰
4. 매칭은 `gecko_id` 1순위, 정규화 심볼·명칭 2순위

실측 52종목(체인 33 · 프로토콜 19). **미매칭 종목은 브리프·대시보드에 항상 노출한다** —
Monad 누락과 SOL 누락의 공통 원인이 "목록에 없으면 원리적으로 안 잡힘"이었기 때문이다.

성과를 보고 편입·제외하면 사후선택 편향이 된다. 변경 시 `universe.py` 의
`INCLUSION_RULE.frozen_at` 을 반드시 갱신한다.

## 센서 — 개별 뉴스가 아니라 '상태 전이'

```
PROPOSED → REVIEW → VOTING → PASSED → SCHEDULED → ACTIVATED
```

| 센서 | 원천 | 비고 |
|---|---|---|
| 거버넌스 제안 | 체인별 improvement-proposal GitHub | API 403 시 commits atom 폴백 |
| 코어 클라이언트 | client repo releases | CI 태그(build-00388) 배제, 레포당 2건 |
| 오프체인 투표 | Snapshot GraphQL | 스페이스별 개별 질의 |
| 온체인 투표 | `rest.cosmos.directory` LCD | 투표 종료일 = 이벤트 예정일 |
| 일정 공지 | Google News RSS | 신뢰도 0.35 할인, 10일 신선도 |

`event_date`(이벤트 예정일)와 `when`(관측일)은 다른 값이다. D-day 는 전자로만 성립한다.

## 점수

```
score = 100 × 임팩트 × 확실성 × 근접도 × 출처신뢰
임팩트   SUPPLY 1.0 / INFRA 0.7 / FEATURE 0.45 / OTHER 0.25
확실성   PROPOSED 0.30 → ACTIVATED 1.00
근접도   D-7 이내 1.00 / D-30 0.85 / D-90 0.60 / 경과 0.10
출처신뢰 1차 원천 1.00 / 릴리스 0.95 / 뉴스 0.35 (예정일 확정 시 ×1.6, 상한 1.0)
```

## 사전등록 — 사후 임계 조정 차단

신규 이벤트는 탐지 시점의 가격·점수를 `registry` 에 박아 저장한다.
D-day 경과 후 T+7 / T+30 초과수익이 자동 축적되므로, 6개월 뒤에는
"어떤 이벤트 유형이 실제로 가격을 움직였나"가 **표본 외**로 남는다.
[[consensus-gap]] 에서 선행신호 가설 4개가 연속 기각된 뒤 허용되는 유일한 검증 경로다.

## 사전등록 채점 (verify.py)

과거 시세 API 를 쓰지 않는다. 탐지 시점의 종목가·BTC가를 `registry` 에 박아두고,
나이가 지평(T+7 / T+30)을 넘긴 이벤트만 그 시점의 현재가로 **한 번만** 확정 기록한다.
재기록을 금지하므로 look-ahead 가 원리적으로 불가능하다.

- 초과수익 = 종목 수익률 − BTC 수익률 (절대수익은 시장 상승을 신호 성과로 오인시킨다)
- 집계는 평균이 아닌 **중앙값** — 동일가중 바스켓 평균은 극단치 1건이 지배한다
- 표본 8건 미만 구간은 수치를 제시하지 않고 '표본 부족'으로 표기한다
