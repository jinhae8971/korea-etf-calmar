# AGI Thesis Radar

Situational Awareness LP 의 **분석 엔진은 복제**하고 **집행 구조는 복제하지 않는**
개인용 투자 인사이트 시스템.

SA 는 논지(AI 인프라 수요)가 옳았음에도 2026년 7월 강제청산됐다.
원인은 논지가 아니라 집행이었다 — 최대 400% 레버리지, 그리고 롱(AI 인프라)과
숏(소프트웨어)이 **동시에 손실을 내면서 헤지가 무력화**된 구조.
이 시스템은 그 실패 지점을 상시 감시하는 계층(L4)을 별도로 둔다.

## 계층

| 계층 | 파일 | 역할 |
|---|---|---|
| L1 논지 그래프 | `config/thesis_graph.yaml` | AI 인과사슬을 노드로 명시화, 노드별 티커 매핑 |
| L2 증거 수집 | `core/prices.py`, `core/funding.py` | 3중 폴백 + 캐시 병합, FRED 서킷 브레이커 |
| L3 토론 | `agents/`, `orchestrator/debate.py` | 4인 에이전트 3-Phase 토론 (선택) |
| L4 리스크 | `core/metrics.py` | 헤지 유효성 · 혼잡도 · 자금조달 스트레스 |
| L5 전달 | `core/render.py`, `docs/` | 텔레그램 브리프 + Pages 대시보드 |

## 핵심 지표

**헤지 유효성** — SA 가 죽은 지점.
`BROKEN` 은 ① 롱 하락 + 숏 상승(동시손실)과 ② 20일 상관 ≤ −0.40 이
**동시에** 성립할 때만 부여한다. 단독 조건은 `WATCH` 까지만.

> 최초 설계는 `spread_vol_ratio ≥ 1.0` 을 붕괴로 봤으나, 상관이 0 근처면
> 이 값은 구조적으로 항상 1을 넘어 전 구간 발동했다(신호로서 무효).
> 실증 후 절대 임계값을 폐기하고 위 복합 조건으로 교체했다.

**혼잡도** — 절대 점수가 아니라 자기 1년 이력의 70/90 분위수로 등급을 매긴다.
경보 빈도가 구조적으로 고정되므로 바스켓을 바꿔도 재보정이 필요 없다.

**병목 이동** — 노드별 20일 초과수익 순위와 그 변화. 순위 1위가 바뀌면
자본이 사슬의 다른 단계로 이동했다는 뜻이다.

## 운영 제약 (하드하게 지켜야 하는 것들)

- **Yahoo Finance 는 GitHub Actions 러너 IP 를 429 차단한다.** 그래서
  Stooq → Yahoo → Nasdaq 3중 폴백 + 레포 커밋 캐시 병합 구조다.
  모든 소스가 죽어도 캐시로 `DEGRADED` 운영된다.
- **텔레그램 발송은 이 레포가 하지 않는다.** Actions Secret 은 값 조회가
  불가하므로 토큰을 옮길 수 없다. 발송은 전략 Agent 봇 토큰을 보유한
  `hynix-correction-monitor` 의 릴레이가 담당한다 (`relay/`).
- **raw.githubusercontent 는 5분 CDN 캐시가 걸리고 `?t=` 로 우회되지 않는다.**
  릴레이는 GitHub Contents API 를 1순위, raw 를 폴백으로 쓴다.
- **공개 레포의 스케줄 워크플로우는 60일간 커밋이 없으면 자동 비활성화된다.**
  이 시스템은 매일 데이터를 커밋하므로 해당 없음.

## 배포 — 모바일 우선 (ghops)

PC 없이 휴대폰 브라우저만으로 배포한다. **zip 을 레포에 올리면 끝.**

### 1회 셋업 (딱 한 번)

호스트 레포 `korea-etf-calmar` 에서:

1. **PAT 등록** — Settings → Secrets and variables → Actions → New secret
   - 이름 `GHOPS_PAT`
   - 값: fine-grained PAT (대상 레포 2개 / Contents:RW, Workflows:RW)
   - PAT 는 GitHub 시크릿에만 존재한다. 채팅·코드·로그 어디에도 남지 않는다.
2. **설치기 워크플로우 생성** — Add file → Create new file
   - 경로 `.github/workflows/ghops-installer.yml`
   - 내용: 이 패키지의 `ops/ghops-installer.yml` 붙여넣기 → Commit

### 이후 모든 배포 (이 프로젝트 포함, 앞으로도 동일)

1. zip 을 휴대폰에 저장
2. 레포 → Add file → **Upload files** → 경로에 `_incoming/` 입력 후 zip 선택
3. Commit

업로드가 `ghops installer` 를 자동 실행한다. 설치기는 zip 안의 `deploy.json`
을 읽어 소스 배치 → 워크플로우 이관(`working-directory` 주입) →
Pages 배치 → 릴레이 푸시 → 워크플로우 트리거까지 수행하고 zip 을 지운다.

> 모바일 브라우저에서 Upload files 버튼이 안 보이면 "데스크톱 사이트 요청"
> 을 켠다. GitHub 모바일 **앱**은 파일 업로드를 지원하지 않는다.

### PC 에서 하는 경우 (대안)

```powershell
.\ops\init_credentials.ps1   # 1회 — PAT 를 DPAPI 로 암호화 저장
.\ops\deploy.ps1             # 이후 무입력 배포
```

`ANTHROPIC_API_KEY` 는 선택이다. 없으면 L3 토론을 건너뛰고 규칙 엔진
판정만으로 정상 동작한다.

## 스케줄

| 요일 | 산출물 | 수집 (KST) | 발송 (KST) |
|---|---|---|---|
| 평일 | 일간 브리프 | 07:10 | 07:20 |
| 토요일 | 주간 리뷰 | 09:00 | 09:10 |
| 일요일 | 다음 주 워치리스트 | 09:00 | 09:10 |

UTC cron: 평일 `10 22 * * 0-4` / 토 `0 0 * * 6` / 일 `0 0 * * 0` (발송은 +10분)

### 주말을 따로 만든 이유

주말은 미국장이 닫혀 새 종가가 없다. 일간 브리프를 그대로 재발송하면
**"시스템이 살아 있는 것"과 "멈춘 것"이 구분되지 않는다.** 그래서 주말은
성격이 다른 산출물로 분리한다.

- **토요일 — 주간 리뷰**: 지난 5거래일 동안 무엇이 바뀌었나 (사후).
  판정 변화, 헤지가 BROKEN 이었던 일수, 노드 순위 변동, 경보 발생 이력.
- **일요일 — 워치리스트**: 각 지표가 임계선까지 얼마나 남았나 (사전).
  "무엇이 얼마나 더 나빠지면 경보인가"를 숫자로 못박아 다음 주 관찰 대상을 고정한다.

둘 다 `history.json` 과 `latest.json` 에서 결정론적으로 계산한다.
예측하거나 지어내는 값은 없다.

주말본은 `docs/data/weekend.json` 에 따로 쓰고, 릴레이는 KST 요일로 읽을 파일을
고른다. 주말 스냅샷이 8시간을 넘으면 **발송하지 않는다** — 지난 주말본이
이번 주말에 재발송되는 사고를 원천 차단한다.
